# color-wheel

Раскладывает реальную палитру по тону и насыщенности на цветовом круге:
видно, что с чем комплементарно, что близко, где дыры. Подход не привязан
к материалу — сейчас наполнен акварельной палитрой для городского скетчинга.

Круги — все краски в наличии, дорожная палитра, теоретический эталон тонов
и наборы художников с дот-карт Daniel Smith — плюс памятка по смешиванию.

Живёт на **https://colors.galangal.ru**.

## Круги

- **Всё в наличии** и **В палитре** — твои краски по тону и насыщенности.
- **Теоретический** — эталонный круг всех тонов (12 секторов), поверх точки
  твоих красок: сразу видно, какие тона покрыты, а где дыры. Клик по краске
  подсвечивает сектор-комплемент напротив.
- **Художники** — второй ряд: выпадающий список и стрелки, чтобы щёлкать
  наборы подряд. Координаты те же, что у твоего круга, поэтому палитры
  сравнимы напрямую. Галочка «моя палитра фоном» подкладывает твои краски
  бледными точками; у общих красок кружок пунктирный.

## Файлы

- **index.html** — страница. Открывается двойным кликом, сервер не нужен.
- **data.js** — рукописная часть: что у тебя есть, как ты это называешь,
  зачем оно нужно, пары, памятка, тексты.
- **catalog.js** — сгенерированная часть: геометрия, цвет и свойства красок
  DS плюс наборы художников. **Руками не править**, пересобирается скриптом.
- **authors/&lt;slug&gt;/** — по папке на художника: `dot-card.avif|jpg`,
  `example.jpg`, `palette.json`.
- **scripts/** — расчёт геометрии и сборка `catalog.js`.
- **deploy.sh** — публикация на colors.galangal.ru.

## Откуда берутся числа

Угол и насыщенность больше не подбираются на глаз. Источник — официальная
[карта CIELab Daniel Smith](https://danielsmith.com/color-map/): в разметке
её точек лежат измеренные `a*`, `b*`, `L*`. Их снимают в `ds-colormap.json`,
дальше `scripts/ds_build.py` переводит Lab → OKLab (минуя sRGB, чтобы не
потерять хрому насыщенных красок на границе гаммы) и раскладывает по
художественной шкале углов.

Насыщенность нормируется на **замороженные** референсы: максимум хромы по
всему каталогу DS в каждой зоне круга, посчитанный один раз. Поэтому новые
краски и новые наборы больше ничего не пересчитывают.

Карта снята с нормальной заливки, а не с масстона, поэтому цвет точки
дополнительно уплотняется одним правилом на весь каталог (`MASSTONE`
в `ds_build.py`) — иначе круг выглядел бы выцветшим.

## Как поменять состав дорожной палитры

Открой `data.js`, найди массив `ACTIVE` и правь список имён:

```js
const ACTIVE = [
  "Hansa Yellow Light",
  "New Gamboge",
  ...
];
```

Имена должны в точности совпадать с полем `n` в `MY`. Если ошибёшься —
страница вверху покажет красное предупреждение с перечнем непонятных имён,
молча ничего не потеряется. То же самое из консоли:

```
python3 scripts/check_data.py
```

Убрал имя из `ACTIVE` → краска пропадает со второго круга, а все рецепты
с ней в памятке гаснут и помечаются «нет в палитре». Добавил → возвращается.

## Как добавить новую краску

Допиши объект в `MY`. Геометрия и цвет не пишутся — они приедут из каталога
по артикулу:

```js
{ sku:"284600025", n:"Cobalt Blue", ru:"Кобальт синий", brand:"Daniel Smith",
  note:"…" },
```

- `sku` — артикул DS. Последние три цифры совпадают с номером на этикетке
  (041 = Hansa Yellow Light), полный номер есть на дот-картах и в
  `scripts/ds-props.json`.
- `n` — короткое имя для подписи на круге; по нему краска зовётся
  в `ACTIVE`, `PAIRS` и `RECIPES`.
- `brand` — что реально стоит в палитре. Если это не DS, геометрия всё равно
  берётся от DS-аналога; где при этом отличается пигмент — скажи об этом
  в `note`.

Дальше пересобрать каталог:

```
python3 scripts/build_catalog.py && python3 scripts/check_data.py
```

Краски без измерений (вся линия Luminescent, эксклюзивы наборов) на карте
CIELab отсутствуют. Такой можно задать `a`/`c`/`hex` прямо в `MY` — они
перебьют каталог; так живёт Duochrome Aquamarine.

## Как добавить художника

Создай папку `authors/<slug>/` и положи туда дот-карту и работу:

```
authors/david-taylor/
  dot-card.jpg     дот-карта Daniel Smith
  example.jpg      работа автора
  palette.json     состав, цитата, био, ссылки
```

`.avif` читается скриптом `scripts/avif_to_png.py` (в системе нет ни PIL,
ни ImageMagick, зато есть libheif — конвертер дёргает её через ctypes).
Состав берётся с карты: на картах до 2022 года под каждой каплей напечатан
артикул, на новых — только имя и серия, тогда краски сводятся по именам.

После этого — `python3 scripts/build_catalog.py`, набор появится в списке.

Источник карт и работ: [Daniel Smith Brand
Ambassadors](https://danielsmith.com/brand-ambassadors/). Работы
принадлежат авторам, на странице стоит подпись и ссылка.

## Кандидаты — чего в наборе нет

Массив `CANDIDATES` в `data.js` — список красок, которых у тебя нет, но которые
стоит рассмотреть. Галочка «кандидаты» у вкладок рисует их на круге пустыми
кружками пунктиром: сразу видно, в какую дыру каждая встанет.

```js
{ sku:"284600187", n:"Transparent Pyrrol Orange",
  ru:"Пиррольный оранжевый прозрачный",
  why:"зачем именно в городском скетчинге…",
  sub:["New Gamboge","Pyrrol Scarlet"],
  subt:"насколько замена честная" },
```

- `sub` — эквивалентная замена замесом, имена из `MY` (пустой массив =
  замесом не воспроизводится, тогда причина в `subt`).
- Правило отбора: кандидат либо закрывает дыру на круге, либо делает то, чего
  замес не даёт (гранулация, кроющесть, прозрачность). Дубли имеющегося
  не берём — почему именно, написано в комментарии над массивом.

Купил краску — перенеси объект из `CANDIDATES` в `MY`, заменив
`why`/`sub`/`subt` на `note`.

## Публикация

Один раз создать каталог (спросит пароль sudo):

```
sudo install -d -o $USER -g $USER /srv/colors
```

Добавить в `/etc/caddy/Caddyfile` блок:

```
colors.galangal.ru {
    root * /srv/colors
    file_server
    encode gzip
}
```

и перечитать конфиг:

```
sudo systemctl reload caddy
```

Дальше при каждом изменении:

```
./deploy.sh
```

DNS (`colors.galangal.ru` → сервер) уже настроен, TLS Caddy выпускает сам.
